# 尘肺胸片标注 · 3D Slicer

用于本地科研读片的简洁模块：六肺区 12 小级密集度、不可评价状态及原因、自动保存、病例切换和 CSV/JSON 导出。当前版本面向单帧 CR/DX 灰度胸片，不生成诊断或自动评分。

## 开始使用

在 Mac 上双击 `启动尘肺标注.command`。启动器使用已安装的 **3D Slicer 5.13.0-2026-10-22**，首次打开相邻工作区的 `2023Sample`，以后恢复上次项目。它不修改平时使用的 Slicer 设置，也不需要另外安装依赖。

1. 确认读者编号。每位医生使用独立编号，避免共用一个编号覆盖记录。
2. 六区默认全部“未评”。选择标准 12 小级，或选择“不可评价”并在备注说明肺区和原因。
3. 评分立即保存，备注停止输入约半秒后保存；切换病例或关闭前会再次保存。保存失败时保留当前输入，阻止切换和关闭，修复后点“重试保存”。
4. “下一例”允许保留草稿；“完成并下一例”要求六区全部已评或标为不可评价，并检查必要的原因。
5. 点击“导出结果”，选择文件夹，生成当前读者的 CSV 与 JSON，包含未评病例和状态。修改已完成病例后会自动回到草稿，须重新完成。

鼠标滚轮缩放、按住中键拖动平移；“适应窗口”恢复全图，“原始灰度”恢复读取的显示灰度。由于样本缺少完整方向信息，界面按原始图像方向显示，并提示核对片内侧别标记。模块不把三维断层方位作为这些胸片的已知解剖方位。

也可在 Slicer 的附加模块路径中加入 `PneumoconiosisAnnotator` 文件夹，重启后在 Research 分类中打开“尘肺胸片标注”。其他机器可设置启动器环境变量 `SLICER_APP` 指向相应的 Slicer 应用。

## 数据与导出

原始 DICOM 只读，不复制进代码仓库。每张图像由 SOP UID 派生稳定项目编号；图像路径、原始 UID 和内容哈希只在本地项目库中关联。重新读取时检查原图哈希，避免图像变化后沿用旧评分。

`local-data/projects/` 保存实际项目，包括 SQLite 标注库及恢复历史。请完整备份 `local-data` 和原始 DICOM 数据。备份时关闭本模块，或使用 SQLite 的在线备份工具；不要只复制仍在写入中的 `.sqlite3` 文件而遗漏 WAL。`local-data/qa/` 是独立测试项目，不是医生标注。

JSON 保留原始 `0/-` 至 `3/+` 字符串、区域可评价状态、备注、读者、病例状态、时间和修改历史，是完整导出。CSV 每区一行，含所有病例；为避免 Excel 将 `0/1` 等改成日期，`profusion_code` 使用 `P0_1` 形式，并另列主级及备选级。`0/-` 对应 `P0_minus`，`3/+` 对应 `P3_plus`，其他级例如 `2/3` 对应 `P2_3`。JSON 的 `grade_codes` 包含完整映射。CSV 中对可能被电子表格解释为公式的自由文本添加前导单引号，原始文字在 JSON 中保持不变。

导出仅包含当前读者和当前目录的项目病例编号，不附源文件路径、患者姓名或原始 DICOM UID。读者编号用于区分记录，**不是登录权限**：本地操作者可以切换编号；需要受控盲读时，为每位读者分配独立的项目数据目录或工作站。不要将正在写入的 SQLite 库放入共享网络盘让多台机器同时使用。

本模块提供六区评分表，不自动确定六区边界，也没有捆绑标准片。六区是胸片读片分区，不是肺叶；应按固定协议和匹配的标准片判读。总体密集度、职业病诊断或分期不由本模块自行推导。

## 验证

纯持久化测试使用标准库：`python3 -m unittest discover -s tests -v`。

Slicer 内测试依次执行 `scripts/slicer_smoke.py`、`scripts/slicer_restore_check.py`，均使用 `--testing --additional-module-path <模块目录> --python-script <脚本>`。它们使用独立 QA 数据库，检查真实控件自动保存、12 个小级、不可评价与原因、跨病例/读者隔离、故障时阻止切换/关闭、全部现有样本读取、原图不变、导出和另一 Slicer 进程恢复。结果及本地界面预览在 `local-data/qa/`，不纳入 Git。
