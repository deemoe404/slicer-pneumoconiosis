# 尘肺胸片标注 · 3D Slicer

用于本地科研读片的简洁模块：整片质量分级、六肺区 12 小级密集度、本地语音录音、自动肺野分割和六区划分、医生手动修正、点 / 多边形标注、自动保存与完整附件导出。面向单帧 CR/DX 灰度 DICOM（`.dcm`），一张胸片对应一条记录；不生成诊断或自动密集度评分。

## 开始使用

在 Mac 上双击 `启动尘肺标注.command`。启动器使用 **3D Slicer 5.13.0-2026-10-22**，首次打开相邻工作区的 `2023Sample`，以后恢复上次项目。它不修改平时使用的 Slicer 设置。当前 Mac 的模型和录音环境已准备；其他机器的首次准备见下文。

1. 在顶部进度行的“读者”下拉框选择 01–10。每位医生使用独立编号，避免共用一个编号覆盖记录。
2. 点击“打开 DICOM 目录”选择胸片总文件夹；子文件夹会一起扫描。原始 DICOM 保持只读。
3. “整片质量”直接点选单选按钮：1 级优片、2 级良片、3 级差片或 4 级废片。默认“未评”，也可点回“未评”；只记录等级，不要求填写质量缺陷原因。历史已记录的原因继续保存在数据和导出中。质量和密集度分别保存。
4. 点“自动肺野 / 六区”。模型在本机后台运行；结果显示为六色叠加，初始为“待医生确认”。可以继续查看其他病例，后台结果只关联其实际来源图像。再次查看已处理图像会恢复缓存。
5. 点“修正肺野”，在原生编辑器中选患者左 / 右肺，用 Paint（画笔）、Erase（橡皮）修改；支持撤销。点“调整分界”后拖动 R-A / L-A（肺尖）、R-D / L-D（膈顶）；分界会按垂直距离三等分重新计算。结束修正后点“确认分区”。任何再次修改都会撤销确认状态。
6. 六区使用六条横向离散滑杆，上方共用标尺标出 `0/-` 到 `3/+` 的全部 12 小级，文字对齐各档刻度；右侧显示准确小级。拖动后松开即保存，也可聚焦滑杆后用左右方向键逐档调整。默认全部“未评”，滑杆的初始位置不生成评分；点“未评”可清除本区评分。选择“不可评”同样算作已评价，不要求填写文字；如需解释原因或补充评价，直接录入语音备注。滑杆上滚轮不改变评分，避免滚动面板时误改。整片质量保留单选按钮；病例、录音、已有点 / 区域仍用下拉列表。模型只划分解剖读片区域，不填写密集度。
7. 评价、不可评价原因及其他补充意见统一通过“语音备注”记录；界面不设文字备注区，录音可选。“语音备注”点“开始录音”，使用系统默认麦克风；停止后可选录音回放。一例可录多段。切换病例、读者或关闭前自动停止并保存，录音随当前胸片和读者关联。初次使用需允许系统麦克风访问。录音保持原声，当前不做语音转写。
8. “点与区域”默认展开，可放点或逐顶点勾画闭合多边形，右键结束；选中后可改名、拖动或删除。未画完的区域保存为草稿，切回后可“继续绘制”。
9. 评分立即保存；质量、坐标及修正停止约半秒后保存。“下一例”保留草稿；“完成并下一例”要求质量和六区均已评、已有分区已确认、已画区域有效；“不可评”是有效结果，可直接完成。影响完成的区域以红框表示未满足、绿框和 ✓ 表示已满足，六个评分行分别变色；按钮颜色汇总全部条件，鼠标悬停可看缺项。可选项留空为绿色，不新增必填项。无需几何分区时可“清除分区”，历史版本仍保留。保存失败时按钮变红，并阻止切换和关闭；当前输入仍保留，修复后点“重试保存”。
10. 点“导出结果”，生成当前读者的完整导出文件夹：评分 CSV、空间坐标 CSV、JSON、WAV 录音、机器与人工修订肺野、六区标签图，包含未评病例和状态。

胸片上方的精简工具栏提供“窗宽窗位”“缩放 / 平移”“适应窗口”“原始灰度”。选择“窗宽窗位”后在片上按住左键拖动，调整明暗和对比度；选择“缩放 / 平移”后用滚轮缩放、中键拖动平移。“适应窗口”恢复全图，“原始灰度”恢复读取的显示灰度。放点或圈选时，查看模式的高亮会自动取消；再点查看工具可结束放置并切回查看。

“完整 Slicer 界面”展开原生工具栏、模块选择器及视图控制，切换其他模块后仍可在图像上方点“精简标注界面”返回当前病例。界面切换不清空评分或标注。界面按原始图像方向显示，患者左右以片内侧别标记核对。模块不把三维断层方位作为这些胸片的已知解剖方位。

也可在 Slicer 的附加模块路径中加入 `PneumoconiosisAnnotator` 文件夹，重启后在 Research 分类中打开“尘肺胸片标注”。其他机器可设置启动器环境变量 `SLICER_APP` 指向相应的 Slicer 应用。

## 首次准备模型与录音

模块的普通读片和评分使用 Slicer 自带组件；模型与录音使用项目专属 `.venv` 后台进程，不把 PyTorch 或音频依赖装进 Slicer，也不改全局 Python。项目用 `mise.toml` 固定 Python 3.12.12；在项目目录执行 `mise exec -- python scripts/prepare_runtime.py`。已有 Python 3.12 的其他机器也可直接运行该准备脚本。

准备脚本按 `requirements-runtime.txt` 安装固定版本依赖，从模型作者官方发布下载约 273 MB 的 ChestX-Det PSPNet 权重，并验证固定 SHA256。权重和环境仅在本机保存。准备完成后，正常读片、模型推理、录音和回放均在本机进行，不上传胸片或音频。Windows 的依赖和路径使用同一套实现，当前实际验收平台是本机 macOS + Slicer 5.13；Windows GUI 尚未实机验收。

模型来源：[TorchXRayVision ChestX-Det 分割模型](https://mlmed.org/torchxrayvision/models.html#chestx-det-segmentation)。六区按现用 GBZ 70-2015 第 3.7 节，用肺尖到膈顶垂直距离的三等分点划分；模型的膈顶点只是中央下缘的初始估计，需要医生核对。六区不是肺叶，也不是将整幅画布或肺野外接框直接三等分。自动掩膜不等于经专家验证的尘肺病灶真值。预处理保留整幅影像，以补边缩放送入模型，再映射回原始像素。

## 数据与导出

原始 DICOM 只读，不复制进代码仓库。每张图像由 SOP UID 派生稳定项目编号；图像路径、原始 UID 和内容哈希只在本地项目库中关联。重新读取时检查原图哈希，避免图像变化后沿用旧评分。

`local-data/projects/` 保存实际项目，包括 SQLite、不可变附件与恢复历史。请完整备份 `local-data` 和原始 DICOM；只备份 `.sqlite3` 会遗漏掩膜和录音。备份时关闭本模块，或使用 SQLite 在线备份并同时保留附件。`local-data/qa/` 是独立功能测试项目，不是医生标注；其中的质量值、修订和录音只用于测试。

每段录音先以可恢复 WAV 分块写入，正常停止后作为附件关联。若写入数据库失败，重试仍保留当前输入；应用意外中断时，重新打开同一项目会检查并恢复已刷盘的未关联片段，不添加空音频。机器肺野与医生修改过的肺野分别保留；每位读者的修订和确认独立。项目锁避免两个标注窗口同时写同一项目。

JSON 保留原始 `0/-` 至 `3/+`、整片质量及原因、区域可评价状态、录音信息、分区状态和定位点、模型版本和权重哈希、读者、时间与修改历史。CSV 每区一行，包含整片质量、分区状态和录音索引；`profusion_code` 使用 `P0_1` 形式避免 Excel 将 `0/1` 改成日期。`0/-` 为 `P0_minus`，`3/+` 为 `P3_plus`；完整映射见 JSON 的 `grade_codes`。新记录和评分 CSV 不再包含文字备注字段；JSON 格式版本为 4。CSV 对可能被解释为公式的标注名称添加前导单引号，JSON 保持原始文字。

导出文件夹的 `assets/` 包含当前记录和历史引用的 WAV、肺野 NPZ；`zone-maps/` 包含各病例六区 NPZ，数组键为 `zones`，尺寸为原图 `[row, column]`，0 为肺野外，1/2/3 为患者右上/中/下，4/5/6 为患者左上/中/下。JSON 的 `partition.zone_map` 保存标签字典和哈希。附件均用相对路径引用，并与 CSV / JSON 一起原子生成。旧记录新增的质量字段保持未评，不自动补造等级；缺少新必填项的旧完成记录恢复为草稿，原有评分和历史保留。

每条 `spatial_annotations` 包含稳定标注 ID、类型 `point` 或 `polygon`、名称、状态 `ready` 或 `draft`，以及 `points_ijk`。坐标使用**原始图像零基像素中心**：I 是列、J 是行、K 固定为 0，原点为原始图像左上像素的中心；允许小数，缩放和平移不改变坐标。区域按顶点顺序闭合，末点连回首点，首点不重复。每个病例包含原图 `columns`、`rows`；顶层 `coordinate_system` 给出坐标约定。`*-spatial.csv` 每个顶点一行，以病例、读者和标注 ID 关联。未完成或交叉的区域在草稿中保留，导出明确标为 `draft`。这些是点和矢量轮廓，不是逐像素分割 mask，也不作为六肺区边界；不输出投影图像的解剖面积测量。

结构化导出不附源文件路径、患者姓名字段或原始 DICOM UID；录音按原声保留，不做内容脱敏。读者编号用于区分记录，**不是登录权限**：本地操作者可以切换编号；需要受控盲读时，为每位读者分配独立项目目录或工作站。不要将正在写入的 SQLite 库放入共享网络盘让多台机器同时使用。

本模块没有捆绑标准片，应按固定协议和匹配标准片判读。总体密集度、职业病诊断或分期不由本模块推导。当前已存在的自动分区也不填写整片质量或六区评分。

## 验证

纯测试使用项目环境：`.venv/bin/python -m unittest discover -s tests -v`，检查持久化、质量、六区几何、不可变附件、WAV 中断恢复、来源 / 读者绑定及完整导出。

Slicer 内依次执行 `scripts/slicer_smoke.py` / `slicer_restore_check.py`、`scripts/slicer_spatial_check.py` / `slicer_spatial_restore.py`、`scripts/slicer_features_check.py` / `slicer_features_restore.py`，使用 `--testing --additional-module-path <模块目录> --python-script <脚本>`。测试使用独立 QA 库；最后一组会实际录入约一秒麦克风音频并回放、对 11 张样本执行真实模型推理、以原生鼠标拖动定位点和橡皮修正肺野，再检查切换、故障保护、完整导出和新进程恢复。报告、预览和测试音频在 `local-data/qa/`，均不纳入 Git。推理成功与几何一致性测试不代表经过医生验收的分割准确率。
